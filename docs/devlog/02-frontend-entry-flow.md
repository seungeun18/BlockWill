# Devlog 02. 사용자용 프론트엔드와 진입 흐름 구현

## 작업 배경

기존 프로젝트는 백엔드 API와 스마트 컨트랙트를 중심으로 구성되어 있어 사용자가 직접 기능을 이용할 수 있는 화면이 부족했다.

사용자가 디지털 유산을 입력하고 분석 결과를 확인할 수 있도록 Vite, React, TypeScript 기반의 사용자용 프론트엔드를 추가했다. 이후 서비스 흐름을 명확하게 만들기 위해 메인 화면, 로그인·회원가입, 사용자 작업 선택 화면을 구현했다.

## 프론트엔드 초기 구성

`frontend` 폴더를 만들고 다음 기술을 사용했다.

- Vite
- React
- TypeScript
- 별도 디자인 라이브러리 없는 CSS
- FastAPI 연동

프론트엔드 API 주소는 `VITE_API_BASE_URL` 환경변수로 관리하며 기본 개발 주소는 `http://127.0.0.1:8001`로 설정했다.

초기 화면에서는 다음 기능을 구현했다.

- 디지털 유산 내용 입력
- `POST /api/estate/analyze` 호출
- 분석된 자산 카드 표시
- 상속 대상과 실행 유형 표시
- 충돌 및 누락 정보 경고
- 분석 근거 펼쳐보기
- 복구 정책 입력
- 복구 정책 검증 및 확인 API 연결
- 로딩, 빈 결과, API 오류 처리

현재 분석 기능은 규칙 기반 데모이므로 실제 LLM 분석이 아니라는 안내를 표시했다. 또한 복구 문구, 개인키, 실제 비밀번호를 입력하지 말라는 보안 문구를 추가했다.

## 사용자 진입 흐름 추가

기존에는 분석 화면이 바로 표시되었지만, 실제 서비스 형태에 맞게 다음 화면 흐름을 추가했다.

1. BlockWill 메인 화면
2. 로그인 또는 회원가입
3. 로그인 후 사용자 작업 선택
4. 나의 디지털 유산 설계하기
5. 기존 디지털 유산 분석 화면

사용자 작업은 다음 두 가지로 구분했다.

- 나의 디지털 유산 설계하기
- 유산 수령 절차 시작하기

이번 스프린트에서는 `나의 디지털 유산 설계하기`를 기존 분석 화면과 연결했다. `유산 수령 절차 시작하기`는 아직 구현되지 않은 기능이므로 다음 스프린트에서 연결된다는 상태만 표시했다.

## 인증 처리

현재 로그인과 회원가입은 전체 화면 흐름을 확인하기 위한 프론트엔드 데모다.

사용자가 폼을 제출하면 브라우저의 `sessionStorage`에 임시 로그인 상태를 저장한다. 같은 탭에서 새로고침하면 로그인 상태가 유지되지만, 실제 사용자 계정이나 비밀번호는 서버에 저장되지 않는다.

실제 인증 API와 데이터베이스 연결은 이후 스프린트에서 구현할 예정이다.

## 디자인

디지털 자산 관리 서비스에 어울리도록 짙은 남색, 청록색, 흰색을 중심으로 구성했다.

- 모바일 반응형 레이아웃
- 접근 가능한 입력 라벨
- 키보드 포커스 표시
- 버튼 비활성 상태
- 로그인 상태가 실제 인증이 아니라는 안내
- 구현되지 않은 기능을 작동하는 것처럼 표시하지 않음

## 검증

다음 명령으로 TypeScript 검사와 프로덕션 빌드를 확인했다.

```bash
cd frontend
npm run build
```

빌드 결과 TypeScript 오류 없이 정상적으로 완료되었다.

## 현재 제한사항

- 실제 회원가입과 로그인 API가 연결되지 않음
- 실제 지갑 연결과 서명이 구현되지 않음
- 유산 수령과 서류 제출 화면이 구현되지 않음
- 현재 AI 분석은 실제 LLM이 아닌 규칙 기반 데모
- 블록체인 트랜잭션은 실행하지 않음
