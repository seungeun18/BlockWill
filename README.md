/*# BlockWill

디지털 유산 상속을 위한 블록체인 기반 유언장 시스템 (Prototype)

---

## 프로젝트 개요

BlockWill은
사용자가 생전에 유언장을 작성하고 암호화하여 안전하게 보관한 뒤,
사망 조건이 충족되었을 때 상속자에게 디지털 자산을 자동으로 이전하는
블록체인 기반 유언 시스템이다.

본 프로젝트는 스마트컨트랙트 + 프론트엔드 + 백엔드(DB)를 연동한
End-to-End 구조를 목표로 한다.

---


### 1. 프론트엔드 기본 구조 구축

* React(Vite) 기반 프론트엔드 구성
* 메인 페이지 / 유언 생성 페이지 분리
* 상태 기반(View State) 화면 전환 구현
* 사용자 입력 UI 정상 동작

---

### 2. MetaMask 지갑 연동

* `window.ethereum` 기반 MetaMask 인식
* 지갑 연결 버튼을 통한 계정 연결
* 연결된 지갑 주소 프론트엔드에 표시
* ethers.js `BrowserProvider`, `Signer` 정상 획득 확인

---

### 3. 유언장 파일 업로드 및 암호화

* 사용자가 파일(txt 등)을 업로드
* 비밀번호 입력 필수
* 브라우저 내에서 FileReader로 파일 내용 읽기
* **CryptoJS(AES)** 를 이용한 유언장 내용 암호화
* 원본 파일은 서버/체인에 저장하지 않음
* 암호화된 문자열만 이후 단계에서 사용

---

### 4. 백엔드 연동 및 유언 데이터 저장

* 백엔드 API (`POST /api/will`) 연동
* 암호화된 유언장을 **SQLite DB**에 저장
* DB에 저장 시 **willId(DB Key)** 자동 생성
* 해당 willId를 이후 블록체인과 연결하는 식별자로 사용

---

### 5. 스마트컨트랙트 설계 및 구현

아래는 **README에 그대로 추가해도 되는 수준**으로
**스마트컨트랙트의 동작 과정을 “실행 흐름 중심”으로 상세히 풀어쓴 설명**이다.
코드 설명이 아니라 **“컨트랙트가 언제, 왜, 어떻게 상태가 변하는지”**에 초점을 맞췄다.

---

## 🔗 스마트컨트랙트 동작 과정 상세 설명

본 프로젝트의 스마트컨트랙트(`Will.sol`)는
**유언 생성 → 생존 관리 → 사망 판정 → 상속 집행**의
명확한 생명주기(Lifecycle)를 갖도록 설계되었다.

컨트랙트는 단순 저장소가 아니라,
**시간(블록) 기반 조건 판단과 자산 이전을 스스로 수행하는 실행 주체**이다.

---

## 1️ 유언 생성 단계 (`createWill`)

### 호출 주체

* 유언자(자산 소유자)

### 호출 시점

* 사용자가 프론트엔드에서 유언장을 작성하고
* 예치 금액을 입력한 뒤
* MetaMask 서명을 승인할 때

---

### 내부 동작 흐름

1. **입력값 검증**

   * 예치 금액(`msg.value`) > 0 확인
   * 상속자 주소가 유효한지 확인

2. **유언 ID 생성**

   * `willCount`를 증가시켜 고유한 `willId` 생성

3. **유언 데이터 저장**

   * 아래 정보가 `wills[willId]`에 저장됨:

     * 유언자 주소 (`owner`)
     * 상속자 주소 (`heir`)
     * 예치 금액 (`deposit`)
     * 현재 블록 번호 (`lastPingBlock`)
     * 생존 주기 (`intervalBlocks`)
     * 유언장 식별자 (`willURI`, DB Key)
     * 비밀번호 힌트 (`secretHint`)

4. **자산 잠금**

   * 전송된 KAIA는 컨트랙트 내부에 보관됨
   * 유언자도, 상속자도 즉시 인출 불가

5. **이벤트 발생**

   * `WillCreated` 이벤트 emit

---

### 이 단계의 핵심 의미

* 자산은 **컨트랙트에 의해 강제로 락업**
* 유언 조건은 **블록체인에 불변 기록**
* 유언자는 이후 **생존을 증명하지 않으면 자동 상속 위험**을 가짐

---

## 2️⃣ 생존 신고 단계 (`ping`)

### 📍 호출 주체

* 유언자 본인만 가능

### 📍 목적

* “나는 아직 살아 있다”는 신호를 블록체인에 남김

---

###  내부 동작 흐름

1. 유언 존재 여부 확인
2. 호출자가 유언자인지 검증
3. 이미 상속 완료된 유언인지 확인
4. `lastPingBlock`을 현재 블록 번호로 갱신
5. `Ping` 이벤트 emit

---

### 이 단계의 핵심 의미

* 컨트랙트는 **실시간 시간을 모름**
* 대신 **블록 번호의 증가**로 시간 경과를 간접 측정
* 생존 신고는 곧:

  > “사망 판정 타이머를 리셋하는 행위”

---

## 3️⃣ 사망 판정 로직 (`isDead`)

### 호출 주체

* 누구나 조회 가능 (읽기 전용)

### 판단 기준

```solidity
block.number > lastPingBlock + intervalBlocks
```

---

### 내부 동작 흐름

1. 해당 유언이 이미 상속 완료되었는지 확인
2. 마지막 생존 신고 블록과 현재 블록 비교
3. 생존 주기를 초과했는지 판단
4. `true / false` 반환

---

### 이 단계의 핵심 의미

* **사망 판정은 자동**
* 관리자, 서버, 외부 개입 없음
* 블록체인의 **결정론적 상태**만으로 판단

즉,

> “누군가 판단한다” 
> “컨트랙트 규칙이 판단한다” 

---

## 4️⃣ 상속 집행 단계 (`claim`)

### 호출 주체

* 상속자만 가능

### 호출 조건

* 사망 판정이 `true`일 것

---

### 내부 동작 흐름

1. **유언 존재 여부 확인**
2. **호출자가 상속자인지 검증**
3. **이미 상속이 실행되지 않았는지 확인**
4. **`isDead(willId)` 호출**
5. 사망 판정 통과 시:

   * `claimed = true` 설정
   * 예치 금액을 상속자에게 전송
   * 내부 deposit 값 0으로 초기화
6. **`Claimed` 이벤트 emit**

---

### 이 단계의 핵심 의미

* 상속자는 **컨트랙트 조건이 만족되기 전에는 아무것도 할 수 없음**
* 사망 판정이 되면 **중개자 없이 즉시 자산 이전**
* 유언자는 사망 이후 **개입 불가**

---

## 5️⃣ 전체 생명주기 요약 (Lifecycle)

```
[createWill]
   ↓
자산 잠금 + 유언 기록
   ↓
[ping] (반복 가능)
   ↓
생존 유지
   ↓
(핑 중단)
   ↓
isDead = true
   ↓
[claim]
   ↓
상속자에게 자산 이전
   ↓
유언 종료
```

---


#### 주요 구조

```solidity
struct WillData {
    address owner;
    address heir;
    uint256 deposit;
    uint256 lastPingBlock;
    uint256 intervalBlocks;
    string willURI;
    string secretHint;
    bool claimed;
    bool exists;
}


---

### 6. 프론트엔드 ↔ 스마트컨트랙트 연동

* ethers.js를 이용한 컨트랙트 인스턴스 생성
* 사용자 입력값을 그대로 스마트컨트랙트 파라미터로 전달

  * 상속자 주소
  * 생존 주기 (블록 단위)
  * DB willId
  * 비밀번호(힌트)
  * 예치 금액
* 트랜잭션 생성 로직 정상 동작 확인
* 트랜잭션 직전 단계까지 모든 파이프라인 검증 완료

---

### 7. End-to-End 흐름 검증 완료 구간

아래 흐름은 **전부 실제 실행으로 검증됨**:

```
사용자
 → 지갑 연결
 → 유언 파일 업로드
 → AES 암호화
 → 백엔드 DB 저장 (willId 생성)
 → 스마트컨트랙트 호출 준비
```

프론트, 백엔드, 스마트컨트랙트가
**논리적으로 정확하게 연결됨이 확인됨**

## 현재까지의 시스템 아키텍처

```
[사용자 브라우저]
  ├─ React Frontend
  │   ├─ MetaMask 연동
  │   ├─ 파일 암호화 (AES)
  │   └─ 스마트컨트랙트 호출
  │
  ├─ Backend API (Node.js)
  │   └─ SQLite DB (암호화된 유언 저장)
  │
  └─ Blockchain
      └─ Will Smart Contract
          ├─ 유언 메타데이터
          ├─ 생존 판정 로직
          └─ 자산 상속 로직
```
